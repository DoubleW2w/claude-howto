Hooks 五类型对比

一条 hook 可以用五种不同方式执行——从最简单的本地脚本，到远程 webhook、再到智能 agent。一眼看清各自机制、通信方式与适用场景。

command
默认 · 最常用 内置
机制
执行 shell 命令
通信
JSON 经 stdin/stdout，退出码决定放行/阻断
适用场景
代码校验 / lint
格式化
日志记录
本地自动化脚本
http
进阶 v2.1.63
机制
调用 远程 webhook
通信
向 URL POST JSON，接收 JSON 响应
适用场景
外部服务集成
团队通知
第三方系统联动
无需本地环境
prompt
进阶 内置
机制
LLM 求值——Claude 求值 prompt
通信
返回 结构化决策（JSON），而非固定退出码
适用场景
Stop / SubagentStop 智能完成检查
需语义判断的任务
非规则化的放行逻辑
mcp_tool
进阶 v2.1.118
机制
调用 已配置的 MCP 工具
通信
引用 server + tool 名，参数走 MCP 协议
适用场景
校验逻辑已在某 MCP server
复用现成工具能力
避免重写脚本
agent
进阶 内置
机制
启动 专用 subagent 评估
通信
可用工具 多步推理，独立上下文
适用场景
复杂架构检查
需调研 + 决策的任务
深度审查
command · 默认
http · 网络
prompt · 智能判断
mcp_tool · 复用
agent · 多步推理
何时选哪种
本地脚本
规则明确、可在本机跑命令 → 选 command
外部服务
要联动远端、团队或第三方 → 选 http
智能判断
需语义/经验决策而非规则 → 选 prompt
复用 MCP
逻辑已在某 MCP server → 选 mcp_tool
复杂多步
需调研 + 推理 + 决策 → 选 agent
一句话原则

从 command 开始——它覆盖绝大多数场景；只有当规则写不进脚本时，才向 http（外部）、prompt（语义）、mcp_tool（复用）、agent（多步）外延。能力越强，开销越大。
