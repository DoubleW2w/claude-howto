Hooks JSON 数据流

Hook 不读命令行参数——它靠 stdin 收 JSON，靠 stdout + 退出码回决策。一条契约，来回两个方向。

关键规则
只有退出码为 0 时，Claude 才解析 stdout 的 JSON；其他退出码下 stdout 被忽略。退出码是「要不要听」的开关，stdout 是「听什么」的内容。
stdin · JSON 输入 Claude → Hook
Claude 通过 stdin 推入的一段 JSON。Hook 从这里读取全部上下文——没有命令行参数。
session_id 当前会话的唯一标识。
transcript_path 对话记录文件路径，可回溯历史。
cwd Claude 当前工作目录。
hook_event_name 触发的事件名，如 PreToolUse。
tool_name 即将调用的工具，如 Edit。
tool_input 工具入参对象——可被 hook 改写后回传。
agent_id 触发的 agent 标识（子 agent 场景）。
agent_type agent 类型，区分主/子 agent。
worktree worktree 隔离信息（启用 worktree 时）。
effort.level 当前推理强度档位。
stdout · JSON 输出 Hook → Claude · 仅退出码 0 时解析
Hook 输出到 stdout 的 JSON。结构字段决定 Claude 后续如何行动。
continue 布尔。是否让 Claude 继续。
stopReason 停止时的理由文本。
suppressOutput 布尔。是否抑制 hook 输出的回显。
systemMessage 要插入给 Claude 的系统消息字符串。
hookSpecificOutput · 按事件类型而变
permissionDecision PreToolUse 专用：allow / deny / ask。
updatedInput 改写后的 tool_input——覆盖原入参。
additionalContext 追加注入的上下文字符串。
退出码 · 决定 Claude 如何对待这次 hook
exit 0

为什么这是关键设计

Hook 是一个黑盒契约：不读命令行参数，全靠 stdin 进、stdout + 退出码 出。任何语言写的脚本，只要遵守这套 JSON 契约，就能介入 Claude 的每一次决策。
