Skills 加载流程 时序

用户一句话触发后，三层按需依次进入上下文窗口——L1 始终在，L2 触发时进，L3 永远不进。

01
用户请求
"审查这段代码的安全问题"
输入 触发点
02
检查元数据
L1 启动时已就绪，Claude 扫描所有 skill 的 name + description
L1 · 已在上下文 ~100 tok / skill
03
匹配 description
把请求语义匹配到某个 skill（如 "审查安全" → security-review）
L1 · 已在上下文 无新增 token
04
读 SKILL.md
L2 指令正文加载进上下文，Claude 获得执行步骤
L2 · 进入上下文 ≤5k tok
05
按需读资源
L3 脚本/模板通过 bash 执行，只取 stdout 结果
L3 · bash 执行 内容不进上下文
06
执行 → 返回
基于 L2 指令 + L3 执行结果，产出审查报告
输出 完成
CONTEXT WINDOW 上下文窗口
上下文内 token：0 / 200k
L1 元数据
L2 指令
200k ctx limit
L3 资源旁路
通过 bash 执行，结果进上下文，源文件不进
L1 元数据 · 始终在上下文
L2 指令 · 触发后进上下文
L3 资源 · 不进上下文
时序的核心

真正进上下文的只有 L1 元数据（启动时已在）和 L2 指令（触发时加载）。 L3 资源无论多大，都通过 bash 执行——只有 stdout 结果回到上下文，源文件永不占用窗口。
