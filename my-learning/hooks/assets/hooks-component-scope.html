Hooks 组件作用域

Hook 不必写死在全局——它可以贴在 skill / agent / command 的 frontmatter 里，与用它的组件放在一起。subagent 的 Stop 还会自动转为 SubagentStop。

作用域对比 · global vs component
全局 settings.json
所有会话、所有组件都生效——跨项目/跨组件的通用 hook。
~/.claude/settings.json
组件 frontmatter
只在该 skill / agent / command 被调用时生效——代码与 hook 放在一起。
SKILL.md / agent.md · YAML frontmatter
skill secure-operations 文件 · secure-operations/SKILL.md
frontmatter · 组件顶部
--- name: secure-operations description: 安全执行敏感操作 hooks: PreToolUse: - matcher: "Bash" hooks: - type: command command: "./scripts/check.sh" once: true --- # SKILL.md 正文 ...
挂载的 hook · 仅本组件触发
PreToolUse
matcher Bash → ./scripts/check.sh
PostToolUse
matcher Edit|Write → ./audit.sh
Stop
无 matcher → ./cleanup.sh
自动转换 · subagent 的 Stop
agent code-reviewer 文件 · agents/code-reviewer.md
frontmatter 写法
Stop
写在 subagent 的 hooks 里
自动转换 仅该 subagent 完成时
实际触发事件
SubagentStop
非主会话停止
subagent frontmatter 里的 Stop 被自动改写为该 subagent 专有的 SubagentStop——只在这个 subagent 结束时触发，不会在主会话每次停止时都跑一遍。
组件容器 · skill / agent / command
生命周期 hook · PreToolUse / PostToolUse / Stop
SubagentStop · 自动转换后的事件
全局作用域 · settings.json
为什么这是关键

把 hook 写进组件 frontmatter，相关代码放在一起——skill 自带它的安全检查，agent 自带它的清理逻辑。而 subagent 的 Stop 自动隔离成 SubagentStop，意味着每个 agent 的收尾互不干扰。
