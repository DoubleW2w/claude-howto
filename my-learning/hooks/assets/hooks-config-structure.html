Hooks 四层嵌套配置

配置是套娃结构——四层从外到内，每层各司其职。看清嵌套，就懂了 hook 怎么挂在事件上。

L1 hooks 顶层容器
hooks: object唯一键
{ "hooks": { // 整个 hook 系统的根 ... } }
包含
L2 "EventName" 事件数组
EventName: [ ]键=事件名
"PreToolUse": [ // 30 种事件之一 ... ]
包含
L3 数组元素 matcher + hooks
matcher: "ToolPattern"可选 hooks: [ ]必填
{ "matcher": "Edit|Write", "hooks": [ ... ] }
包含
L4 hook 定义 叶子对象
type: "command"必填 command: "..."必填 timeout可选 once可选
{ "type": "command", "command": "./pre-commit.sh", "timeout": 60 }
关键字段速查
matcher 工具名匹配模式，如 Edit|Write。省略则匹配该事件下所有工具。
hooks hook 定义数组——真正要执行的命令都挂在这里。
type 目前唯一取值 command——hook 是一条 shell 命令。
command 实际执行的 shell 命令字符串。stdin 收 JSON，退出码决定放行/阻断。
timeout 秒数上限，超时则 kill。默认 60。
once 布尔。为 true 时整个会话只跑一次。
L1 hooks · 顶层容器
L2 EventName · 事件数组
L3 matcher + hooks · 数组元素
L4 hook 定义 · 叶子对象
为什么这是关键

这四层是 hooks 配置的骨架——hooks 装事件，事件装 matcher 分组，分组装命令。理解了套娃嵌套，就理解了「hook 怎么挂在事件上」。
