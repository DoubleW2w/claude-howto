# Prompt 模板

4 个可直接复制使用的 Prompt 模板，对应四步操作法。所有示例输出均用 Checkpoints 演示。

| 模板 | 用途 | 对应步骤 | 适用场景 |
|------|------|---------|---------|
| [骨骼提取](#1-骨骼提取) | 提取目录/概念/API表，不看正文 | 第二步"抓取骨骼" | 手头有文档，需快速建立知识地图 |
| [核心提炼](#2-核心提炼) | 二八法则筛出 4-6 张核心概念卡 | 第三步"提取核心" | 已完成骨骼提取，需进一步聚焦 |
| [去噪精简](#3-去噪精简) | 砍重复解释、评价废话、冗余示例 | 第四步"去噪成文" | 已提取核心，需整理成最终笔记 |
| [快速入门](#4-快速入门) | 组合三步，从零掌握新领域 | 全流程 | 接触新工具/新框架，30 分钟建立核心认知 |

---

## 1. 骨骼提取

**用途**: 第二步"抓取骨骼" —— 只提取结构信息，不看正文内容。

**适用场景**: 手头有文档、网页或教程，需要快速建立知识地图，判断值不值得深入学。

### Prompt

```text
分析以下文档，只提取结构信息，不要正文内容：

1. 完整的目录树（含所有标题层级）
2. 核心概念列表（≤10 个，每个一行）
3. 关键命令/API/快捷键表（如有）
4. 配置项/设置项清单（如有）

输出格式：Markdown 表格和列表。禁止输出解释性文字。
```

## 2. 核心提炼

**用途**: 第三步"提取核心" —— 用二八法则从骨骼中筛出必须掌握的内容。

**适用场景**: 已完成骨骼提取，需要从 10 个概念中锁定 4-6 个关键点，避免信息过载。

### Prompt

```text
以下是我对 [领域名称] 的骨骼分析。请应用二八法则做核心提炼：

骨骼内容：
[粘贴模板1的输出]

要求：
1. 从核心概念中只筛选 4-6 个"必须掌握"的，给出判断理由
2. 标记哪些内容是"用的时候再查"级别的
3. 为每个核心概念写一张概念卡（名称、一句话定义、最简用法示例）
4. 最终保留率控制在 20-30%

输出格式：Markdown，每个概念卡用 ### 标题。
```

### Checkpoints 示例输出

将 Checkpoints 骨骼输出粘贴进去后，得到：

```markdown
### 概念卡 1：Checkpoint

- **定义**：每次用户输入时自动创建的对话快照，包含消息、文件修改和上下文。
- **用法**：无需手动操作，正常对话即可自动生成。
- **筛选理由**：一切操作的基础，不搞清楚"checkpoint 是什么"后面的都理解不了。

### 概念卡 2：Rewind

- **定义**：回到之前的 checkpoint，丢弃该点之后的所有更改。
- **用法**：按 `Esc`+`Esc` 打开 checkpoint 浏览器，选择目标 checkpoint，再选择恢复方式。
- **筛选理由**：Checkpoints 的核心价值——能回退才有意义。

### 概念卡 3：5 个恢复选项

- **定义**：回退时可选的 5 种恢复方式。
- **用法**：
  - 恢复代码和对话 — 全部回退
  - 恢复对话 — 只回退消息
  - 恢复代码 — 只回退文件
  - 从这里开始总结 — 压缩后续对话
  - 算了 — 取消
- **筛选理由**：知道有哪些选项直接决定回退操作是否正确；选错选项可能导致丢失代码或对话。

### 概念卡 4：分支探索模式

- **定义**：在某个 checkpoint 分叉，先后尝试多个方案，对比后选择最佳。
- **用法**：保存基准 checkpoint → 尝试方案 A → 回退 → 尝试方案 B → 对比 → 选择。
- **筛选理由**：这是 Checkpoints 最高价值的使用模式，直接对应 80% 的实际使用收益。

**保留率：~25%**（原文约 330 行，核心概念卡覆盖 4 个要点）

**标记为"用的时候再查"**：
- 配置项 `cleanupPeriodDays` 的具体取值
- 故障排查步骤
- 与 Git 的集成细节
- 自动清理机制
```

## 3. 去噪精简

**用途**: 第四步"去噪成文" —— 砍掉评价性语言、重复解释、冗余示例，保留实质技术内容。

**适用场景**: 已提取核心内容（自己的笔记或模板 2 的输出），需要精简为干净的参考文档。

### Prompt

```text
将以下内容精简为最简可用版本。

原始内容：
[粘贴模板2的输出或自己的笔记]

精简规则：
1. 删除所有评价性语言（"很重要""非常有用""不可或缺"等）
2. 删除重复的解释段落
3. 每个概念只保留一个最简示例
4. 保留所有技术细节（命令、快捷键、配置值、限制说明）
5. 如果原始内容已经足够精炼，不要为了压缩而压缩

输出格式：干净的 Markdown。
```

### Checkpoints 示例输出

以 Checkpoints "5 个恢复选项"内容演示去噪前后的差异：

```markdown
## 去噪前（含评价性语言）

Checkpoints 是 Claude Code 的一个非常强大的内置自动功能，
让你可以安全地探索不同方案而无需担心丢失工作。
它在探索不同方案、从错误中恢复或比较替代实现时非常重要。

Checkpoints 允许你保存对话状态并回退到之前的任意时间点。
这是对话状态的快照，包含了所有已交换的消息、已做出的文件修改、
工具使用历史和会话上下文。

## 去噪后

| 概念 | 说明 |
|------|------|
| Checkpoint | 对话快照，含消息、文件修改、上下文 |
| Rewind | 回到之前 checkpoint，丢弃后续更改 |
| Esc+Esc | 打开 checkpoint 浏览器 |
| /rewind | Slash 命令，同 Esc+Esc |
```

## 4. 快速入门

**用途**: 组合模板 1+2+3，从零开始快速掌握一个陌生领域。一次对话完成骨骼提取、核心提炼、去噪精简全流程。

**适用场景**: 接触新工具、新框架、新概念，30 分钟内建立可用级别的核心认知。

### Prompt

```text
我要学习 [领域名称]。请按以下步骤帮我快速掌握核心知识：

第一步：列出该领域的骨骼结构（目录/核心概念/关键命令表/配置项表）。禁止输出正文。

第二步：用二八法则从骨骼中筛选 ≤6 个核心概念。对每个核心概念，给出：
- 名称
- 一句话定义
- 最简用法示例（一个）

第三步：列出 3 个最容易踩的坑。

输出格式：干净的 Markdown。禁止评价性语言。禁止重复。如果原始内容已经精炼，不再压缩。

参考信息源：
[粘贴或列出文档链接]
```

### Checkpoints 示例输出

将 `[领域名称]` 替换为 `Claude Code Checkpoints`，参考信息源填入 `08-checkpoints/README.md` 和官方文档链接后，一次性输出骨骼结构 + 核心概念卡 + 常见陷阱。

这个模板的输出结果与 `my-learning/checkpoints/README.md` 的结构直接对应：骨骼对应目录概览，核心概念卡对应核心概念速查表，常见陷阱对应三不要（不替代 git、不依赖跟踪外部变更、不过度依赖）。

---

## 使用建议

- **顺序使用**: 模板 1 → 2 → 3 逐步推进，每步产出都是下步输入
- **单独使用**: 根据自己的进度，可以只用其中某一个模板
- **组合使用**: 时间紧时直接用模板 4，一次对话完成全流程
- **重复使用**: 同一组模板可用于任何领域，只需替换输入文档
